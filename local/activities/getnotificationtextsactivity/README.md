# Получение текстов уведомлений

Собственная PHP-активити для коробочного Битрикс24. Общий каталог — любой доступный инфоблок, в том числе универсальный список 407. Активити ничего не изменяет в инфоблоке и не отправляет уведомления: возвращает готовые строки для стандартных действий.

## Установка

1. Скопировать всю папку `getnotificationtextsactivity` в `<корень сайта>/local/activities/`. Не переносить файлы непосредственно в `activities`: имя вложенной папки и файла класса должны сохраниться.
2. Дать веб-серверу чтение файлов. Файлы в UTF-8 без BOM; реализация рассчитана на сайт в UTF-8 и PHP 7.1+ с совместимой версией Битрикс. На актуальной коробке использовать поддерживаемую ядром версию PHP.
3. Проверить, что установлены модули `iblock` и `bizproc`, а `/local/activities/getnotificationtextsactivity/ajax.php` доступен через веб-сервер. Эндпоинт требует авторизации, POST, действующей сессии и прав чтения выбранного инфоблока/элемента.
4. Переоткрыть конструктор бизнес-процесса. Активити называется «Получение текстов уведомлений», категория — «Прочее». При необходимости очистить кеш списка активити средствами Битрикс.
5. Разместить её перед действием уведомления или задания. Если значения меняются между шагами, использовать отдельное получение перед каждым нужным шагом.

Автоматическое создание/изменение списка 407 не выполняется. Его реальная структура в этой рабочей среде недоступна.

## Структура каталога

Каждый элемент — один шаблон с несколькими текстами. Точное назначение полей выбирается в активити, поэтому создавать обязательные коды свойств не нужно. Доступны `NAME`, `PREVIEW_TEXT`, `DETAIL_TEXT` и активные одиночные строковые свойства, включая HTML/текст. Свойства справочников, привязки и множественные свойства не предлагаются.

Рекомендуемая структура при создании нового каталога:

| Выход | Поле или строковое свойство |
| --- | --- |
| Название задания | NAME или отдельное свойство TASK_TITLE |
| Текст задания | DETAIL_TEXT или TASK_TEXT |
| Тема письма | MAIL_SUBJECT |
| Текст письма | MAIL_TEXT |
| Текст уведомления на сайте | PREVIEW_TEXT или SITE_TEXT |

По умолчанию: название задания — `NAME`, текст задания — `DETAIL_TEXT`, уведомление на сайте — `PREVIEW_TEXT`; почтовые поля не выбраны. Для неиспользуемого выхода выбрать «Не использовать»: результат будет пустой строкой.

Инфоблок и элемент сохраняются по ID; свойства — по ID внутри выбранного инфоблока. При переносе в другую базу настройки нужно сопоставить заново. Элемент должен оставаться активным. Расписание дат активности элементов не используется.

## Настройка в конструкторе

1. Выбрать инфоблок, затем элемент-шаблон.
2. Указать, из каких полей брать пять текстов.
3. Заполнить автоматически найденные параметры кнопками вставки значения: переменные, константы, поля документа, результаты предыдущих активити или обычный текст.
4. Для HTML-текстов включить «Экранировать значения для HTML». Экранируются только значения параметров, разметка самого шаблона сохраняется. Для обычного текста и BBCode оставить выключенным. HTML-шаблоны должны редактироваться доверенными пользователями; параметр нельзя использовать как непроверенный URL, JavaScript или CSS. Для ссылок передавать заранее проверенный адрес и использовать поддерживаемый каналом формат.
5. Сохранить активити и бизнес-процесс.
6. В стандартном действии выбрать «Вставка значения → Дополнительные действия → [название этой активити] → [нужный результат]».

Выходы имеют постоянные имена:

| Имя результата | Подпись |
| --- | --- |
| TaskTitle | Название задания |
| TaskText | Текст задания |
| MailSubject | Тема письма |
| MailText | Текст письма |
| SiteText | Текст уведомления на сайте |

Пример шаблона задания:

```text
Договор № {{contract_number}}

{{recipient_name}}, согласуйте договор до {{deadline}}.
Срок согласования: {{approval_days}} дней.
```

Имена параметров регистрозависимы: латинские буквы, цифры и `_`, первый символ — буква или `_`. Пробелы внутри скобок допустимы: `{{ deadline }}`. Один параметр во всех выбранных полях требует одного соответствия.

В инфоблоке **не использовать** `{=Variable:...}` или `{=Constant:...}`. Выбирать эти выражения в соответствиях активити. Тексты каталога и подставленные строки повторно не вычисляются. Значение `{{another_parameter}}` внутри значения останется буквальным текстом.

Константа/переменная вычисляется на шаге выполнения. Дату заранее привести к нужному формату; пользователя — к имени/ссылке. Массивы строк соединяются через `, `. Пустое вычисленное значение допускается; пустое соответствие при сохранении — ошибка. `0` сохраняется как `0`.

## Изменения шаблона и права

- Изменение текста с прежними параметрами сразу учитывается при следующих выполнениях активити, включая уже запущенные процессы, ещё не дошедшие до шага.
- Уже созданные задания и отправленные уведомления не обновляются.
- После добавления параметра открыть использующие шаблон активити, нажать «Обновить параметры шаблона» и заполнить новое соответствие. Старые значения сохраняются по имени параметра при обновлении формы. При переключении инфоблока соответствия очищаются.
- Если новый параметр появился после сохранения процесса, выполнение завершится ошибкой до возврата текстов. Ошибки не заменяются молча пустыми значениями.
- При удалении/деактивации элемента или удалении выбранного свойства выполнение завершается ошибкой.
- В форме и AJAX проверяются права текущего пользователя. Во время выполнения чтение осуществляется как системное действие бизнес-процесса, без проверки прав случайного пользователя текущего HTTP-запроса. Поэтому каталог должен содержать только тексты, доступные процессам, использующим эти шаблоны; права редактирования каталога и конструктора нужно настроить соответственно.

## Проверки

В репозитории есть автономные проверки `tests/getnotificationtextsactivity/run.php`:

```sh
php tests/getnotificationtextsactivity/run.php
```

Они проверяют подстановку, ошибки, контракты настройки и выполнения с заменителями API Битрикс. Проверены PHP-синтаксис и JavaScript-синтаксис. Полного ядра Битрикс и доступа к порталу в рабочей среде нет: интеграционная проверка конструктора пока не выполнена.

При установке проверить на тестовом процессе:

1. Выбрать список 407 и шаблон, сопоставить реальные поля; убедиться, что список параметров обновляется без закрытия формы.
2. Вставить переменную и константу кнопкой выбора, сохранить, переоткрыть и проверить сохранность соответствий.
3. Подставить результаты в название/текст задания, письмо и уведомление на сайте. Убедиться, что все пять выходов видны в «Дополнительных действиях».
4. Выполнить процесс с кириллицей, нулём, пустой переменной и символами `<>&` в HTML-письме.
5. Изменить текст каталога и выполнить ещё раз; добавить параметр без соответствия и проверить понятную ошибку.
6. Проверить поведение после завершения сессии и под пользователем без прав чтения каталога.
