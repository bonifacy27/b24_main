# Дашборд группы 163

Адрес после размещения: `/forms/marketing/dashboard.php`.

Скопируйте три файла из `forms/marketing/` в одноимённую папку сайта:
`dashboard.php`, `dashboard_metrics.php`, `dashboard_config.php`.
Требуется PHP 7.1+ и установленный модуль tasks. Существующий `view_tasks_KO.php`
не меняется. Дашборд не изменяет задачи и базу данных.

Авторизация обязательна. Список ID получает `CTaskItem::fetchListArray` с
`MAKE_ACCESS_FILTER=true`, аналогично `view_tasks_KO.php`. Дополнительные записи
истории, тегов, участников и времени читаются исключительно для разрешённых ID.
Поэтому результаты разных пользователей могут отличаться.

## Настройка

В `dashboard_config.php`:

- `group_id` — 163;
- `stage_map` — точное сопоставление ID стадий канбана четырём этапам
  (`new`, `work`, `review`, `done`). Без него используются статус задачи и
  автоматическое сопоставление названий стадий. Проверьте соответствие стадий
  «Согласование» на вашем портале; завершение определяется статусом 5;
- `holidays` и `working_dates` — официальные переносы выходных по годам.
  По умолчанию исключены суббота, воскресенье и ежегодные праздники РФ;
  без настройки переносов это пятидневка с праздниками, а не полный
  производственный календарь;
- `timezone` — Europe/Moscow.

Существующие теги выбираются в пяти независимых фильтрах. Для направления,
продукта, приоритета и уровня РК выберите соответствующий тег; все условия
соединены по И. Жёсткого словаря значений и вымышленных тегов нет.

## Расчёты и ограничения

Проект — корневая задача. В отчёт входят созданные до конца периода задачи,
кроме завершённых до начала периода. Теги наследуются от корня. Недоступные
корни не входят в количество проектов и обозначаются в таблице отдельно.
Фильтры не влияют на видимость корней и не отключают проверки прав.

Воронка и состояние проектов — на конец периода, для текущего периода на
момент обновления. Состояние восстанавливается обратным применением истории
STATUS и STAGE_ID. «Новая / отложена» включает статусы 1, 2, 6, 7;
«В работе» — 3, «Согласование» — 4, «Завершена» — 5. Канбан-стадии
могут уточнять незавершённые задачи. Отклонённые не считаются зависшими.

Рабочие дни — включительно от DATE_START, либо CREATED_DATE, корневой задачи
до завершения или конца периода, включая паузы. Трудозатраты — SECONDS
из b_tasks_elapsed_time по CREATED_DATE записи и USER_ID исполнителя.
Показаны часы на сотрудника, проект и сотрудника внутри проекта.

В срок — завершённые за период задачи с текущим дедлайном. Задачи без срока
исключены из знаменателя. Возврат — STATUS 4/5 → 1/2/3 или стадия
согласования → работа. Два таких события одной задачи в одну секунду считаются
одним возвратом. Атрибуция возвратов — текущему ответственному, не автору записи.
Без движения — последняя активность/изменение или запись истории раньше конца
периода; порог N задан в календарных днях.

Сравнение: текущий месяц/квартал по момент обновления против полного предыдущего.
Для произвольного интервала предыдущий имеет ту же длину в календарных днях.
Назначения, теги и дедлайны берутся текущие. Исторические переприсвоения,
изменения дедлайна и удалённые события не восстанавливаются. CLOSED_DATE
отражает последнее закрытие, поэтому повторные завершения одной задачи
не считаются отдельными завершёнными задачами.

При отсутствии схемы журнала или времени связанные показатели показывают
«Нет данных». Наличие таблицы не гарантирует полноту её истории. Если база
отличается от штатной схемы, сообщения об этом выводятся на дашборде.
Поддерживаются обе схемы тегов: прямой TASK_ID и связующая b_tasks_task_tag.

## Проверки

`php tests/marketing_dashboard/run.php` проверяет расчёты без Битрикс.
PHP-синтаксис всех трёх файлов проверен на PHP 8.2.

Перед эксплуатацией на сервере проверьте:
1. Под обычным пользователем видны те же задачи, что в группе 163.
2. Корень и подзадачи объединяются в один проект.
3. Реальный возврат и запись времени совпадают с журналом задачи.
4. Стадии согласования и производственный календарь настроены правильно.

Проверка на реальной базе и публикация в работающем портале в этой среде
не выполнены: доступны только исходники репозитория.
